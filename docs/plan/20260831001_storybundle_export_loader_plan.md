## Plan: StoryBundle Export and Loader

### TL;DR
Build a new Rust `storyscript-bundle` library/CLI and a separate Flutter FFI package, `storyscript_bundle`, for exporting and loading signed `.storybundle` files. A bundle is a deterministic ZIP container with no raw `.StoryScript` source: it carries a versioned Protobuf semantic IR, required assets, a bounded manifest/index, and an Ed25519 signature. Projects are defined by `StoryScript.toml`; export uses a sandboxed parser resolver, statically discovers literal assets, requires explicit globs for dynamic asset templates, and pins the exact StoryScript compiler version plus Protobuf schema hash. The loader is generic rather than player-integrated, requires a host-provided trust store by default, exposes the full verified model to Dart through shared generated Protobuf types, and enforces a cross-platform 100 MiB hard resource profile.

**2026-08-31 Progress:**
- Discovery, requirements alignment, and risk assessment are complete. No implementation phase has started; Phases 1-9 remain pending.
- Confirmed boundaries: no raw source, no encryption/DRM claim, no `storyscript-player` integration, exact compiler-version matching, `.storybundle` extension, LGPL-2.1, Rust core plus Flutter wrapper, package-ready delivery without registry publication.

### Implementation Steps

#### Phase 1: Parser Safety Foundation — make project compilation bounded, diagnosable, and sandboxed
- Update `parser/rust/src/compiler.rs` with a project-root/source-resolver boundary used by a new project compile entry point. Resolve the root and every `@include` through one normalized project-relative path policy; reject absolute paths, parent traversal, symlink escape, non-files, invalid UTF-8 source, and duplicate normalized/case-folded paths before reading. Preserve source-order merging and keep `compile_source` behavior explicit for raw source without a resolver.
- Keep `compile_file` source-compatible for `player/src/runtime.rs`, but route it through the safe filesystem resolver rooted at the root script's parent. Add a separate explicit-project-root API for `storyscript-bundle`, so an entry script below the project root cannot widen the include sandbox.
- Fix `parser/rust/src/lexer.rs::read_number` so oversized integer/decimal literals produce a structured compile-time diagnostic instead of panicking. Reuse `E_SYNTAX` only if its trigger is documented precisely; otherwise add `E_NUMERIC_LITERAL_INVALID` consistently in `PLAN.md` and `parser/rust/src/diagnostic.rs`.
- Fix root parsing so missing, repeated, or out-of-order `* INIT` emits the existing `E_INIT_COUNT`/`E_INIT_ORDER` contract instead of returning `script: None` with no diagnostic. Treat `script.is_none()` as a hard compiler failure even when diagnostics are unexpectedly empty.
- Add `parser/rust/tests/compiler_project.rs` for resolver behavior, include ordering, parent/absolute/symlink rejection, duplicate normalized names, missing INIT, child-module merging, and backward compatibility of valid `compile_file` callers. Extend the inline tests in `parser/rust/src/lexer.rs` for oversized integer and decimal input without a panic.
- Update the parser diagnostic mapping in `PLAN.md`; explicitly verify that no StoryScript syntax, player runtime behavior, or VS Code token/completion behavior changes in this phase.
- **Checkpoint**: Valid root/child projects still compile in source order; malformed numerics and malformed INIT structures return diagnostics; include reads cannot escape the selected root. `player` still compiles against the compatibility API. Safe to stop here — the existing parser/player chain remains coherent and the new safe compiler boundary is independently usable.
- **Checkpoint Verification**: Run `cargo test --manifest-path parser/rust/Cargo.toml && cargo check --manifest-path player/Cargo.toml --no-default-features`.

#### Phase 2: Contract and Schema Foundation — freeze the v1 project, archive, IR, and compatibility contracts
- Create `bundle/proto/storybundle/v1/compiled_story.proto` as the canonical semantic IR schema. Cover every semantically reachable type and variant in `parser/rust/src/ast.rs`: initialization data, variables and exact types, actor portraits, logic blocks, PREP/STORY statements, branches, loops, choices, expressions, decimal literals, BGM path-versus-STOP, dialogue forms, positions, and asset references.
- Encode interpolated strings as ordered literal/variable segments. Convert the parser's internal escaped-dollar marker into literal `$` data; do not preserve `${...}` source syntax, comments, formatting, filenames, include paths, REQUIRE contracts, or line/column metadata. Represent decimals losslessly with a canonical decimal string that preserves scale; do not use floating-point fields.
- Avoid Protobuf `map` fields in signed/deterministic data. Use ordered repeated records and stable enums/oneofs; define required-presence and recursion/nesting invariants in the contract even where proto3 itself cannot enforce them.
- Create the `bundle/rust/Cargo.toml`, `bundle/rust/build.rs`, `bundle/rust/src/lib.rs`, `bundle/rust/src/contract/`, `bundle/rust/src/config.rs`, `bundle/rust/src/error.rs`, and `bundle/rust/src/limits.rs` foundations. Add the minimal `bundle/rust/src/main.rs`/`cli.rs` `schema check` command needed for a contract checkpoint. Expose the exact `storyscript-parser` compiler version from `parser/rust/src/lib.rs`; require `StoryScript.toml` to pin that exact version.
- Define `StoryScript.toml` authoring semantics: project ID/name/version, root entry script, exact compiler version, asset root, literal asset policy, and explicit dynamic files/globs. Signing-key paths are CLI inputs and must never be persisted in the project descriptor.
- Define the `.storybundle` ZIP layout in `docs/contracts/storybundle_v1.md`: reserved `META-INF/storybundle/` metadata/signature entries, one compiled Protobuf payload, normalized `assets/` entries, fixed compression/metadata rules, no source entries, and rejection of unknown/unlisted entries.
- Define a reproducible schema fingerprint derived from the pinned Protobuf descriptor set. Check in the `.proto` source, descriptor fingerprint, and generated Dart output later; do not serialize `parser/rust/src/ast.rs` directly.
- Add `bundle/rust/tests/contract_v1.rs` for descriptor/schema-hash stability, exact compiler pin parsing, Protobuf required-invariant failures, decimal scale, all AST variant coverage, and proof that source-only fields are absent.
- **Checkpoint**: The v1 contract and crate skeleton compile, every current AST semantic variant has an explicit Protobuf representation, and exact compiler/schema identity rules are testable before exporter or loader code exists. Safe to stop here — dependent implementations can build against a stable contract without inventing fields independently.
- **Checkpoint Verification**: Run `cargo test --manifest-path bundle/rust/Cargo.toml --test contract_v1 && cargo run --manifest-path bundle/rust/Cargo.toml -- schema check`.

#### Phase 3: Rust Project Compiler and Asset Graph — turn a validated project into deterministic semantic IR plus required assets
- Implement `bundle/rust/src/project.rs` to load and validate `StoryScript.toml`, canonicalize the project/entry/asset roots, enforce the exact parser version pin, and invoke the Phase 1 sandboxed compiler API.
- Implement exhaustive AST-to-Protobuf conversion under `bundle/rust/src/ir/v1/`. Preserve source ordering and semantic distinctions while stripping all source-only metadata. Fail closed on an unhandled enum/statement variant; add an exhaustive conversion test so future AST additions cannot silently disappear from bundles.
- Implement template compilation under `bundle/rust/src/template.rs`, using `parser/rust/src/interpolation.rs` behavior as the semantic reference. Produce literal/variable segments for narration, dialogue, choices, actor display names, string expressions, portrait paths, and `@bg`/`@bgm`/`@sfx` paths.
- Implement asset discovery under `bundle/rust/src/assets.rs`. Traverse actor portraits and all asset directives, including directives nested in logic, PREP branches, and loops. Add literal paths automatically. For each dynamic template, require configured files/globs, require at least one compatible normalized match, and include the complete matched set. Fail export for missing literals, unmatched dynamic declarations, duplicate logical paths, absolute/parent paths, symlink escape, case-fold collisions, and files outside the asset root.
- Normalize archive logical paths to UTF-8 POSIX separators and one Unicode normalization form. Sort the final asset index by normalized logical path; never derive signed order from `HashMap` iteration.
- Create `bundle/rust/tests/fixtures/demo_project/` with a root script, included child module, actor portrait, background, BGM/SFX, dynamic asset variants, and tiny valid image/audio assets. Keep this as authoring input only; tests must assert that the exported output contains no `.StoryScript` entry or source-only comment/format data.
- Add `bundle/rust/tests/project_compile.rs`, `bundle/rust/tests/ir_conversion.rs`, and `bundle/rust/tests/asset_discovery.rs` for valid compilation, every AST family, include order, exact version mismatch, literal/dynamic asset closure, path safety, deterministic ordering, and current `example/*.StoryScript` semantic conversion where those examples do not require absent media.
- **Checkpoint**: A `StoryScript.toml` project can be compiled into an in-memory, deterministic v1 IR and closed asset graph, but no archive is emitted yet. All source validation and asset-closure failures are typed. Safe to stop here — the compiler result is independently tested and no incomplete bundle format is exposed.
- **Checkpoint Verification**: Run `cargo test --manifest-path bundle/rust/Cargo.toml --test project_compile --test ir_conversion --test asset_discovery`.

#### Phase 4: Rust Exporter, Signature, and Export CLI — emit deterministic signed `.storybundle` files
- Implement `bundle/rust/src/manifest.rs`, `bundle/rust/src/archive/writer.rs`, `bundle/rust/src/signing.rs`, and `bundle/rust/src/exporter.rs`. The manifest records format version, exact compiler version, schema hash, project metadata, normalized entry names, entry type, compression mode, compressed/uncompressed sizes, SHA-256 digest, signer key ID, and resource-limit profile.
- Sign a domain-separated digest of the exact deterministic manifest bytes with Ed25519. Keep the signature in the reserved metadata area; cover the compiled payload and every asset through manifest digests. Reject any attempt to omit a compiled/asset entry from the signed index.
- Accept signing material in the Rust library as caller-owned PKCS#8 PEM bytes or a signer abstraction. The CLI accepts `--signing-key` as an external path, reads it for the shortest possible lifetime, never logs it, zeroizes sensitive buffers where supported, refuses a key path inside the selected project/repository root, and commits no private key. Tests generate ephemeral keys in temporary storage.
- Make output reproducible for identical project bytes, compiler/schema identity, options, and signing key: sorted entries, fixed ZIP timestamps/permissions, deterministic compression selection, deterministic JSON field ordering, and no host path/build timestamp leakage.
- Enforce export-side hard ceilings: archive and total uncompressed payload at most 100 MiB, each entry at most 64 MiB, compiled IR at most 16 MiB, manifest at most 1 MiB, no more than 4,096 entries, plus contract-defined path and semantic nesting limits. Hosts may lower but not raise these ceilings.
- Extend `bundle/rust/src/main.rs`/`bundle/rust/src/cli.rs` from the Phase 2 `schema check` foundation with a typed `export` command, human-readable output, and stable machine-readable JSON diagnostics. Require the `.storybundle` extension unless the caller explicitly selects stdout/library bytes.
- Add `bundle/rust/tests/export_determinism.rs`, `bundle/rust/tests/signing.rs`, and `bundle/rust/tests/cli_export.rs` for byte-identical repeat exports, no raw source, manifest coverage, signature correctness, key-path rejection, limit failures, and non-zero CLI exit behavior.
- **Checkpoint**: The Rust API and CLI emit a signed, deterministic `.storybundle` from the canonical fixture, and low-level tests prove every payload entry is indexed and no source is shipped. Safe to stop here — exported artifacts are complete and versioned even though consumer loading arrives next.
- **Checkpoint Verification**: Run `cargo test --manifest-path bundle/rust/Cargo.toml --test export_determinism --test signing --test cli_export`.

#### Phase 5: Rust Hardened Loader and Verification CLI — validate untrusted bundles before exposing content
- Implement `bundle/rust/src/archive/reader.rs`, `bundle/rust/src/trust.rs`, `bundle/rust/src/validator.rs`, and `bundle/rust/src/loader.rs` with a fail-closed validation pipeline: preflight file size; bounded ZIP directory parse; normalized-name, duplicate, case-collision, encryption, special-file, and unknown-entry checks; bounded manifest parse; host trust-key lookup; signature verification; exact format/compiler/schema match; entry size/hash validation; bounded Protobuf decode; then semantic IR validation.
- Never extract archive entries to the filesystem. Keep assets archive-backed and expose bounded reads by normalized logical path. Do not return manifest content as trusted, compiled model bytes, or asset bytes until all strict checks succeed.
- Model the host trust store as key-ID-to-Ed25519-public-key data supplied by the embedding application. Default to strict trusted-signature verification. Make unsigned loading available only through an explicitly named development policy; surface that state in verification metadata and prohibit accidentally constructing it as the default.
- Add stable structured Rust/CLI error codes for malformed archive, path collision, resource limit, malformed manifest, unknown signer, bad signature, digest mismatch, unsupported format, compiler mismatch, schema mismatch, Protobuf decode, semantic IR violation, missing asset, and disallowed unsigned bundle.
- Complete `inspect` and `verify` CLI commands. `inspect` may show bounded envelope metadata as explicitly untrusted before verification, but must not decode/expose the semantic model; `verify` requires a supplied trusted public key/trust store and performs the complete pipeline.
- Add adversarial fixtures generated in tests rather than committed secrets/huge files: ZIP traversal, absolute paths, duplicate/case aliases, unlisted extras, oversized declarations, high compression ratio, malformed/recursive Protobuf, missing oneof, wrong hashes, wrong key, altered manifest, altered asset, unsigned strict-mode, compiler mismatch, and schema mismatch.
- Add `bundle/rust/tests/loader_security.rs`, `bundle/rust/tests/signature_policy.rs`, `bundle/rust/tests/version_compatibility.rs`, `bundle/rust/tests/limits.rs`, and `bundle/rust/tests/cli_verify.rs`. Add a bounded fuzz target under `bundle/rust/fuzz/` for archive-envelope and Protobuf decode entry points, with seed cases from the adversarial tests.
- **Checkpoint**: Rust can round-trip a valid signed bundle and reliably reject each malformed/tampered/version-incompatible class without panic, extraction, or content exposure. Safe to stop here — the standalone Rust library/CLI fulfills export and generic-load responsibilities independently of Flutter.
- **Checkpoint Verification**: Run `cargo test --manifest-path bundle/rust/Cargo.toml --test loader_security --test signature_policy --test version_compatibility --test limits --test cli_verify`.

### UI & Screen Planning Details
- **Screen / Surface Inventory**:
  - **Bundle Inspector** (`storyscript_bundle/example/`, route `/`, `example/lib/features/bundle_inspector/bundle_inspector_screen.dart`): Demonstrates the generic Flutter loader to package evaluators. Entry is the example app after `RustLib.init`; dependencies are an injected `StoryBundleLoader`, strict host trust store containing only the public fixture key, `BundleInspectorController`, and the signed fixture bytes. The surface shows a load action, signature/trust and exact compiler/schema status, project metadata, semantic-model summary/tree, asset list, and image preview. It must render explicit empty, loading/progress, verified, unknown-signer, bad-signature, compiler/schema mismatch, malformed/oversized, missing/decode-failed asset, and disposed states. Use a compact stacked layout below the established 768px example breakpoint and split metadata/model/assets panels on wider screens. ### Architectural Decisions & Scope Boundaries
- **In-Scope**: `StoryScript.toml`; safe parser project resolver and parser crash/diagnostic fixes; dedicated v1 Protobuf semantic IR; literal/variable string segments; no-source deterministic ZIP `.storybundle`; required literal/dynamic assets; SHA-256 index; Ed25519 signing via caller bytes/CLI external key path; host trust store; strict signature default and explicit unsigned development mode; exact compiler SemVer plus schema hash; hard 100 MiB cross-platform profile; Rust library/CLI export/inspect/verify/load; Flutter all-platform FFI loader; full typed Dart Protobuf model; bounded asset reads; Bundle Inspector; focused CI/tests/docs/package metadata.
- **Explicitly Excluded**: Raw `.StoryScript` source or source maps in bundles; encryption, DRM, or a promise that semantic text/assets cannot be recovered; automatic compiler/schema migration; compatibility ranges; multi-gigabyte/streaming bundles; registry publication; remote/network trust or certificate PKI; player/runtime integration; image/audio decoding as a library responsibility; BGM/SFX playback; changes to existing `storyscript_player_core` APIs/UI; Cargo workspace reorganization; REST/RPC/database/SQL changes.
- **Assumptions**: `.storybundle` is binary but standard ZIP-readable; hiding raw source means source text/comments/layout are absent, not confidential. The signed manifest plus complete entry hashes is the authenticity boundary. Consumers provision trusted public keys outside bundles. The exporter and loader support one exact compiler/schema identity at a time. Assets and compiled IR fit the fixed ceilings. Dynamic asset globs are author-declared and export fails if they cannot close a dynamic template. The root LGPL-2.1 license applies to both new packages. No plan overlaps or journal dependencies exist because `docs/plan/` and `journal/` were absent before this plan.
- **Impacted Modules & Ownership**: Rust language/core: `parser/rust/`, `bundle/proto/`, `bundle/rust/`. Flutter/plugin: new `storyscript_bundle/` and its example/platform wrappers. Shared: `PLAN.md`, `README.md`, `docs/`, `.gitignore`, `.github/workflows/`. Existing runtime compatibility only: `player/`, `storyscript_player_core/rust/` compile checks. Cross-module lockstep is mandatory among the `.proto` descriptor hash, Rust generated model/converter, exact compiler identity, Dart generated model, FRB bridge metadata, fixture, docs, and CI generation diff. No Backend (`server/`), Flutter application (`app/`), Data Platform (`supabase/`), or SQL modules exist here.

### Risk & Security Assessment
- **Identified Risks**:
  - `[HIGH]` — **Signer Private-Key Exposure**: Consumers use raw unencrypted PKCS#8 key material, and the current repo has no generic key ignore/secret-scan policy. **Mitigation**: accept caller-owned bytes and an external CLI path only; refuse keys inside the project/repo root; never persist/log key data; minimize/zeroize memory; generate ephemeral test keys; commit only a public fixture key; add ignore rules, secret scanning, and explicit operational warnings.
  - `[HIGH]` — **Signature/Manifest Substitution or Canonicalization Bypass**: Ambiguous serialization, unlisted ZIP entries, or duplicate names could let verified metadata diverge from consumed bytes. **Mitigation**: sign domain-separated exact manifest bytes; index/hash every payload entry; reject extras, duplicates, aliases, and unknown reserved entries; use fixed deterministic serialization; verify trust/signature and all entry hashes before exposure; add mutation tests.
  - `[HIGH]` — **Archive Traversal and Decompression/Allocation DoS**: ZIP paths, symlinks, duplicate/case aliases, forged sizes, high ratios, or too many entries can exhaust memory or escape storage. **Mitigation**: never extract; normalize and validate names before lookup; reject special/encrypted entries; enforce 100/64/16/1 MiB and 4,096-entry ceilings plus nesting/path limits in Dart and Rust; hosts may lower only; adversarial and fuzz tests.
  - `[HIGH]` — **Untrusted Protobuf Semantic Abuse**: A signed or unsigned-development payload can contain malformed oneofs, unknown enum values, excessive recursion, invalid references, or values the compiler could never emit. **Mitigation**: decode only after envelope/signature/version/hash checks; cap payload/depth/node counts; run a dedicated v1 semantic validator; fail closed on unknown/impossible variants; never deserialize directly into runtime AST; fuzz the decoder.
  - `[HIGH]` — **Parser Panic/Silent Failure During Export**: Current numeric parsing uses `unwrap`, and missing INIT may yield no script/no diagnostics. **Mitigation**: Phase 1 parser hardening and regression tests are a prerequisite; exporter additionally treats absent script or any error diagnostic as a hard typed failure.
  - `[MEDIUM]` — **Web/FFI Memory Amplification**: Bundle bytes copy into Wasm and verified Protobuf copies back into Dart; current Web builds cap Wasm memory at 1 GiB. **Mitigation**: reduce the agreed profile to 100 MiB on every platform, async APIs, preflight before FFI/allocation, 16 MiB IR cap, lazy per-asset reads, no all-asset Dart cache, and boundary memory tests.
  - `[MEDIUM]` — **Compiled Content Misunderstood as Confidential**: Protobuf and the full Dart model expose narrative strings/identifiers, and ZIP exposes assets. **Mitigation**: omit raw source/comments/layout/source maps, but state prominently that this is casual opacity rather than encryption/DRM; do not market content as unrecoverable.
  - `[MEDIUM]` — **Exact-Version Availability Lock-In**: No source fallback and exact compiler/schema matching can strand bundles when an application upgrades. **Mitigation**: deterministic incompatibility errors, preserve matching package artifacts/releases operationally, document coordinated upgrades/rollback, and require re-export before moving consumers. Automatic migration is explicitly deferred.
  - `[MEDIUM]` — **Generated Contract Drift**: Protobuf descriptor, Rust code, Dart code, FRB bindings, schema hash, fixtures, and docs can diverge. **Mitigation**: pin generators, one canonical `.proto`, checked fingerprint, generated-file diff CI, cross-language fixture tests, and exact identity checks.
  - `[MEDIUM]` — **Dependency/Supply-Chain Expansion**: ZIP, Protobuf, crypto, hashing, TOML/glob/normalization, FRB, and Dart Protobuf dependencies enlarge the attack surface. **Mitigation**: minimal features, pinned direct versions/code generators, `cargo audit`, license/advisory policy, lock/reproducibility checks in CI, and avoid custom archive/crypto implementations.
  - `[LOW]` — **Dirty Working Tree/Generated Binary Contamination**: Existing unrelated iOS/native artifacts and modified files can be accidentally staged with new generated output. **Mitigation**: implementation begins with status review, stages paths intentionally, keeps build outputs ignored, and uses generated-diff allowlists; this plan does not overwrite current user changes.
- **Data Sensitivity**: Bundles may contain proprietary story text, images, and audio and may incidentally contain PII authored into content. No raw source is shipped, but semantic content and assets remain recoverable at runtime and at rest; signing supplies authenticity/integrity, not confidentiality. The libraries add no telemetry, network transfer, retention store, or data-residency behavior. Hosts remain responsible for content rights, privacy classification, storage, and transport security.
- **Dependency & Supply-Chain Risks**: New Rust dependencies likely include a ZIP reader/writer, `prost`/pinned `protoc`, SHA-256, Ed25519/PKCS#8, serialization/TOML, glob matching, Unicode normalization, zeroization, and test/fuzz tools; Flutter adds generated Protobuf and retains pinned FRB/Cargokit. Pin generator/runtime compatibility, disable unused archive algorithms/features, audit advisories/licenses, and verify generated output. Do not implement ZIP, SHA-256, Ed25519, or Protobuf primitives manually.
- **AuthN / AuthZ Gaps**: There is no end-user authentication or authorization layer. Publisher authentication is the host-provided trust store: a key embedded only in the bundle is never trusted. Unknown keys and unsigned bundles fail by default; development bypass is explicit and observable. Key rotation/revocation is host policy/documentation scope; remote revocation services and certificate chains are excluded.
